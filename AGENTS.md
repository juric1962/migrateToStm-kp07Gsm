# Project Instructions — Mega128 to STM32F405 Migration

## 1. Цель проекта

Данный проект переносится с микроконтроллера ATmega128 на STM32F405.

Исходный проект Mega128 является рабочим эталоном.

Цель миграции — получить функционально эквивалентный проект для STM32F405 под:

* IAR Embedded Workbench for ARM 7.x
* STM32F405
* выбранную периферию STM32

Главный принцип:

**Сначала сохранить поведение существующей программы, затем при необходимости улучшать архитектуру.**

---

Исходный проект Mega128 является REFERENCE.

Файлы исходного Mega128 проекта:

**НЕ изменять без моего явного разрешения.**

`STM32_IAR/`

Codex НЕ должен самостоятельно переносить весь проект целиком.

Перед началом каждого этапа я должен явно указать, что именно необходимо перенести.

* "Перенеси UART0"

* "Перенеси обработчики прерываний"

Если я не указал следующий этап, не начинай его самостоятельно.

# 4. Анализ перед изменением

Перед переносом любого блока:

1. Найди весь код Mega128, относящийся к этому блоку.
2. Определи его назначение.
3. Найди связанные переменные.
4. Найди функции, которые используют этот блок.
5. Найди связанные прерывания.
6. Определи настройки периферии.
7. Определи временные параметры.
8. Определи зависимости от других периферийных блоков.

Перед изменением сообщи краткий план.

Не начинай реализацию, если неясно, как работает исходный код.

---

# 5. Не выполнять механический перевод регистров

Не выполнять простой перевод:

AVR register → STM32 register.

Сначала необходимо понять функциональное назначение исходного кода.

Например:

AVR Timer1 может использоваться как:

* системный таймер;
* генератор периодического события;
* источник PWM;
* счётчик;
* временная база.

Необходимо перенести именно функцию, а не название регистра.

При миграции необходимо по возможности сохранить:

---

# 7. Прерывания

Прерывания являются критической частью проекта.

Для каждого ISR Mega128 необходимо определить:

* источник;
* условие возникновения;
* частоту;
* используемые переменные;
* вызываемые функции;
* изменяемое состояние программы.

Создавать таблицу соответствия:

| Mega128            | STM32F405                    |
| ------------------ | ---------------------------- |
| ISR(...)           | соответствующий IRQ/Callback |
| TIMER interrupt    | TIM interrupt                |
| ADC interrupt      | ADC interrupt/callback       |
| UART interrupt     | USART interrupt              |
| External interrupt | EXTI                         |

Особое внимание уделять переменным, которые используются одновременно в основном коде и ISR.

Не изменять семантику ISR без моего разрешения.

---

# 8. Таймеры

Для каждого таймера необходимо определить:

* clock source;
* prescaler;
* counter mode;
* period;
* compare value;
* overflow frequency;
* interrupt frequency;
* назначение таймера.

Проверять фактическую частоту работы таймера математически.

Если исходный Mega128 таймер генерировал событие каждые 1 ms, STM32 должен обеспечивать эквивалентное временное поведение.

Не считать перенос правильным только потому, что проект компилируется.

---

# 9. ADC

При переносе ADC необходимо учитывать:

* reference voltage;
* resolution;
* channel;
* sampling time;
* conversion mode;
* trigger source;
* interrupt;
* DMA;
* частоту преобразований.

Если ADC Mega128 работал в циклическом режиме или использовал прерывание, сохранить это поведение.

---

# 10. UART / USART

Для каждого UART определить:

* baud rate;
* data bits;
* parity;
* stop bits;
* RX/TX;
* interrupt mode;
* buffering;
* обработчики ошибок.

Не менять протокол обмена без моего разрешения.

---

# 11. GPIO

Для каждого используемого GPIO определить:

* port;
* pin;
* direction;
* pull-up/pull-down;
* initial state;
* alternate function;
* active level.

Особенно внимательно проверять:

* active LOW;
* active HIGH;
* входы с подтяжкой;
* выходы, которые должны иметь определённое состояние сразу после reset.

---

# 12. IAR 7.x

Проект должен быть совместим с:

**IAR Embedded Workbench for ARM 7.x**

Не использовать возможности языка, библиотек или инструментов, которые требуют более новой версии IAR, если они не поддерживаются IAR 7.x.

Не предполагать GCC-совместимость.

Если код или библиотека потенциально несовместимы с IAR 7.x, сообщить об этом до использования.

# 13. Структура STM32 проекта

Все новые файлы должны находиться внутри:

`STM32_IAR/`

Предпочтительная структура:

```text
STM32_IAR/
├── Project/
├── Core/
├── Inc/
├── Src/
├── Drivers/
├── Startup/
├── Linker/
├── CMSIS/
└── HAL/
```

Структуру можно изменить, если это необходимо для конкретного проекта, но не создавать ненужные каталоги.

# 19. Проверка функциональной эквивалентности

Для каждого перенесённого блока сравнивать:

Mega128:

```text
INPUT
   ↓
PERIPHERAL
   ↓
INTERRUPT / EVENT
   ↓
APPLICATION
```

с STM32:

```text
INPUT
   ↓
PERIPHERAL
   ↓
IRQ / CALLBACK / DMA
   ↓
APPLICATION
```

Цель — сохранить функциональное поведение.
